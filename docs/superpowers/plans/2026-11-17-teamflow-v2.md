# TeamFlow version 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild TeamFlow as a three-role, role-aware project platform with dependencies, resources, discussions, scored reviews, internal notes and a three-number dashboard.

**Architecture:** Static HTML/CSS/vanilla ES modules on Supabase. Every permission lives in Postgres (grants, RLS through `private.*` helpers, SECURITY DEFINER functions with fixed `search_path`). One Edge Function (`send-invitation`) emails invitations through Resend while calling the database as the inviter.

**Tech Stack:** Supabase Auth, Postgres 15+ (column-list `ON DELETE SET NULL`), PostgREST, Storage, Deno Edge Function, `@supabase/supabase-js@2.119.0`, `lucide@1.73.0`, `monaco-editor@0.52.2` from jsDelivr.

**Spec:** the "Version 2 (to approve)" tab of the TeamFlow design doc (approved 17 Nov 2026), which argues from the attached "TEAMFLOW Complete Product Specification".

## Global Constraints

- Roles: `profiles.platform_role` in (`user`, `platform_admin`); `project_members.role` in (`member`, `team_leader`). No other role exists.
- No GitHub anywhere: submission types are exactly `code`, `text`, `file`.
- Scores are integers 0 to 100, required on approval, absent on a revision request; feedback required on a revision request.
- Personal dashboard shows exactly: Assigned Tasks, Completed Tasks, Average Score.
- Invitations: 7-day expiry, SHA-256 hash stored, one pending per (project, email), single use, email and confirmation must match.
- Files: submissions bucket private 10 MB; task-resources private 20 MB with extension and MIME allow-lists; avatars public 2 MB.
- Never execute submitted code. Never ship a secret key in the frontend. Never bypass RLS.
- Copy rules: plain sentence-case UI text, no em dashes, errors say what happened and how to fix it.

## Review Focus

1. A Team Leader who is also assigned a task in their own project: must never be able to review or read internal notes on their own submission. Test in Task 1 (`leader cannot review own work`, `notes hidden from author-leader`).
2. Deadlines near midnight in the project's time zone (Cairo vs UTC): a deadline typed as 23:30 local must store and display as 23:30 local. Test in Task 5 (`zonedToUtc('2026-11-20T23:30','Africa/Cairo')` equals `2026-11-20T21:30:00Z`).
3. Concurrent dependency inserts forming a cycle (A->B and B->A at once): the project lock must make the second fail. Test in Task 1 (`second half of a cycle is refused`).
4. Removing a member with a pending submission and completed work: their completed count and average stay intact in `member_performance`. Test in Task 1 (`performance survives removal`).
5. Uploading a resource file whose name says `.pdf` but whose path points outside the task folder: refused by the storage policy and by the resource trigger. Test in Task 1 (`resource path must sit under its task`).

- `resend_invitation(p_invitation_id uuid) -> jsonb` (same shape), `revoke_invitation(p_invitation_id uuid) -> void`
- `get_invitation(p_token text) -> jsonb {project_name, email, invited_by_name, status, expires_at}` (also `anon`)
- `accept_invitation(p_token text) -> uuid` (project id)
- `remove_member(p_project_id uuid, p_user_id uuid) -> void`
- `start_task(p_task_id uuid) -> void`
- `add_task_dependency(p_task_id uuid, p_depends_on uuid) -> uuid`, `remove_task_dependency(p_task_id uuid, p_depends_on uuid) -> void`
- `task_prerequisites(p_task_id uuid) -> table(task_id uuid, title text, status text, assignee_name text)`
- `set_comment_pinned(p_comment_id uuid, p_pinned boolean) -> void`
- `submit_solution(p_task_id uuid, p_code text, p_language text, p_text text, p_file_path text, p_file_name text) -> jsonb {id, version}`
- `review_submission(p_submission_id uuid, p_decision text /* approve | request_revision */, p_feedback text, p_score int, p_internal_note text) -> void`
- `add_internal_note(p_submission_id uuid, p_content text) -> uuid`
- `member_performance(p_user_id uuid, p_project_id uuid default null) -> jsonb {assigned_tasks, completed_tasks, average_score}`
- `overview_stats() -> jsonb` (security invoker: counts the caller may see)
